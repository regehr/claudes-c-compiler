# Commits On `yarpgen` After `61f1d2996750df77e2ab524225ea33e76ed47f4f`

- [`9addd3af`](https://github.com/regehr/claudes-c-compiler/commit/9addd3af0a16eb0f86633622afbe5be975fd6e33) (`fix`) - Bug fix: **Yes**. The parser was treating `int;`-style non-aggregate declarations inside `struct`/`union` bodies as if they were anonymous members. That created a fake field slot and could shift initializer mapping to real fields, producing wrong initialized values.
- [`f9edd2ab`](https://github.com/regehr/claudes-c-compiler/commit/f9edd2ab4dd8cc9c8f820c0aa592a03bb75af922) (`fix`) - Bug fix: **Yes**. Global initializer lowering used a `sub_stride > struct_size` gate that failed for singleton inner dimensions (`[1]`). This prevented needed recursion through brace nesting and mis-initialized multidimensional struct arrays.
- [`06d5dcce`](https://github.com/regehr/claudes-c-compiler/commit/06d5dccea49750bc317188977cd5b22bbfca512d) (`fix`) - Bug fix: **Yes**. Constant folding for `||` and `&&` could fold from the RHS even when LHS truthiness was unknown. That violates short-circuit semantics and could wrongly skip LHS side effects.

- [`4c0a8fb9`](https://github.com/regehr/claudes-c-compiler/commit/4c0a8fb960a033a8185ba584ac2537aa011cb787) (`fix`) - Bug fix: **Yes**. In global struct-array init lowering, the flat index tracker (`current_idx`) was not advanced after consuming nested elements. Excess scalar initializers could be reprocessed at an older index and overwrite the last valid element.
- [`55c50b38`](https://github.com/regehr/claudes-c-compiler/commit/55c50b38c411e06830bf805c8f58e6d485a598d7) (`add back yarpgen-only tester`) - Bug fix: **No**. This restores a YARPGEN fuzzing harness script (`yarpgen_diff.py`) and does not modify compiler behavior.
- [`78e8e7fb`](https://github.com/regehr/claudes-c-compiler/commit/78e8e7fb5b5eb9a38f880e3ce376985c55034e3e) (`fix`) - Bug fix: **Yes**. Small packed structs carried in registers were sometimes stored/loaded using carrier widths (`I32`/`I64`) directly against exact-size objects. That could clobber adjacent bytes on stores and read out of bounds on loads for odd sizes (for example 5-7 bytes). The fix routes these paths through exact-width stores or temporary+`memcpy` handling.
